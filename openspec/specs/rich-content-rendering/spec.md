## Requirements
### Requirement: Markdown の描画
システムは、投稿されたポストの本文を Markdown として解釈し、整形された表示を行わなければならない (SHALL)。対応記法は見出し、強調、リスト（順序付き／順序なし／タスク）、引用、リンク、水平線、表、インラインコードを含まなければならない (SHALL)。

#### Scenario: 基本記法を描画する
- **WHEN** ポスト本文に見出し・強調・リスト・引用を含む Markdown が含まれる
- **THEN** システムはそれぞれを対応する視覚表現へ変換して表示する

#### Scenario: 表を描画する
- **WHEN** ポスト本文に Markdown の表記法が含まれる
- **THEN** システムは表として描画し、横幅を超える場合は表の内部で横スクロールさせる

#### Scenario: リンクを開く
- **WHEN** ユーザーが描画された本文中のリンクをクリックまたはタップする
- **THEN** システムは既定のブラウザで当該 URL を開き、アプリ自身の画面遷移は発生させない

### Requirement: 危険な入力の無害化
システムは、Markdown 描画時に埋め込まれたスクリプトおよび危険な HTML を実行してはならない (MUST NOT)。

#### Scenario: 埋め込みスクリプトを含む本文
- **WHEN** ポスト本文にスクリプトタグやイベントハンドラ属性を含む HTML が記述されている
- **THEN** システムはそれらを実行せず、無害化した上でテキストとして表示する

#### Scenario: 危険なスキームのリンク
- **WHEN** ポスト本文にスクリプトを実行するスキームのリンクが含まれる
- **THEN** システムは当該リンクを実行可能な形で描画しない

### Requirement: コードブロックのシンタックスハイライト
システムは、フェンス付きコードブロックを等幅フォントの独立ブロックとして描画し、言語指定がある場合はシンタックスハイライトを適用しなければならない (SHALL)。

#### Scenario: 言語指定のあるコードブロック
- **WHEN** ポスト本文に言語を指定したフェンス付きコードブロックが含まれる
- **THEN** システムは当該言語の構文に従って色分けし、等幅フォントで表示する

#### Scenario: 言語指定のないコードブロック
- **WHEN** ポスト本文に言語指定のないフェンス付きコードブロックが含まれる
- **THEN** システムはハイライトを適用せず、等幅フォントのプレーンなコードブロックとして表示する

#### Scenario: 未対応言語の指定
- **WHEN** コードブロックにハイライタが対応していない言語が指定される
- **THEN** システムはエラーを表示せず、ハイライト無しのコードブロックとして描画する

#### Scenario: 長い行を含むコードブロック
- **WHEN** コードブロック内に表示幅を超える行が含まれる
- **THEN** システムはコードブロック内で横スクロールを提供し、ポスト全体のレイアウトを崩さない

### Requirement: コードのコピー
システムは、コードブロックの内容をクリップボードへコピーする操作を提供しなければならない (SHALL)。

#### Scenario: コードをコピーする
- **WHEN** ユーザーがコードブロックのコピー操作を実行する
- **THEN** システムはコードブロックの生のテキストをクリップボードへ格納し、完了したことを示すフィードバックを表示する

### Requirement: Mermaid 図の描画
システムは、言語指定が `mermaid` のコードブロックを図としてレンダリングしなければならない (SHALL)。**描画は投稿が確定したポストに対してのみ行い、入力中のライブプレビューを行ってはならない (MUST NOT)。** 描画に失敗した場合はポスト全体の表示を壊してはならない (MUST NOT)。

#### Scenario: 有効な Mermaid 定義
- **WHEN** 投稿済みのポスト本文に構文的に正しい `mermaid` コードブロックが含まれる
- **THEN** システムは対応する図を描画し、コードの代わりに図を表示する

#### Scenario: 不正な Mermaid 定義
- **WHEN** `mermaid` コードブロックの構文が不正でレンダリングに失敗する
- **THEN** システムはエラーである旨を示した上で元のコードをコードブロックとして表示し、他のポストの描画は継続する

#### Scenario: 編集後に再描画する
- **WHEN** ユーザーが `mermaid` コードブロックを含むポストを編集して保存する
- **THEN** システムは保存後の本文に対して図を描画し直す

#### Scenario: 図とソースを切り替える
- **WHEN** ユーザーが描画済み Mermaid 図のソース表示切り替え操作を実行する
- **THEN** システムは図と Mermaid ソースコードの表示を切り替える

#### Scenario: 大きな図を表示する
- **WHEN** 描画された図がポストの表示幅を超える
- **THEN** システムは図を表示領域に収めるか、図の内部でスクロール／拡大表示できるようにする

#### Scenario: 可視範囲に入ってから描画する
- **WHEN** Mermaid を含むポストがタイムラインの可視範囲外にある
- **THEN** システムは当該ポストの図の描画を行わず、可視範囲に入った時点で描画する

### Requirement: 描画のテーマ追従
システムは、コードハイライトおよび Mermaid 図の配色を、アプリのライト／ダークテーマに追従させなければならない (SHALL)。

#### Scenario: ダークテーマへ切り替える
- **WHEN** ユーザーがアプリの表示テーマをダークへ切り替える
- **THEN** システムはコードブロックの配色と Mermaid 図の配色をダーク向けの配色へ更新する

### Requirement: プラットフォーム間での描画の一致
システムは、Electron・PWA・iOS のいずれにおいても、同一のポスト本文に対して意味的に同じ描画結果を提供しなければならない (SHALL)。

#### Scenario: 同じポストを各クライアントで見る
- **WHEN** Markdown、コードブロック、Mermaid を含む同一のポストを Electron・ブラウザ・iOS で表示する
- **THEN** システムはいずれの環境でも同じ要素（見出し・リスト・ハイライト済みコード・図）を表示する
