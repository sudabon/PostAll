## Context

`frontend/` は React 19 + Vite + Tailwind CSS v4 + shadcn/ui（`@theme inline` + CSS 変数パターン）で構成されています。現状は次の状態です。

- `src/index.css` は shadcn の既定 slate パレットをほぼそのまま保持し、トークンは色と `--radius` のみです。タイポグラフィスケール、余白スケール、エレベーション、材質のトークンは存在しません。
- モーションの実装は `transition-colors`（`button.tsx`、`ReactionBar.tsx`）と `transition-opacity`（`PostActions.tsx`、`ReactionBar.tsx` のツールチップ）、`animate-pulse`（`AttachmentGallery.tsx`）の 5 箇所のみで、バネもジェスチャ追従もありません。アニメーションライブラリは未導入です。
- 検索・設定のオーバーレイはネイティブ `<dialog>` + `showModal()` で、出入りのアニメーションはありません。
- `AppShell.tsx` のサイドバー境界は `pointermove` を `window` に直接登録する実装で、ポインタキャプチャ・速度履歴・境界での抵抗を持ちません。ヘッダーは `h-11` の不透明な固定ストリップに `border-b` です。
- `AppShell.tsx` のヘッダーには素の `<button>`（「折りたたむ」）が残っており、共通コンポーネントを経由していません。
- 既存の検証環境は Vitest（jsdom）+ Playwright です。`data-testid`（`sidebar`、`channel-title` など）が E2E の足がかりになっています。

制約として、同じ成果物を Electron シェル（Chromium）が同梱するためブラウザ差異の考慮範囲は Chromium と主要モダンブラウザに限られます。バックエンド API とデータモデルには一切触れません。`mobile/` は Flutter の別実装であり本変更の対象外です。

## Goals / Non-Goals

**Goals:**

- 視覚的な値（色・字送り・余白・角丸・影・材質）を単一のトークン層へ集約し、コンポーネントからリテラル値を排除する。
- バネ・中断可能性・速度の引き継ぎ・ラバーバンディングを、少数の共有プリミティブ（フック/ラッパーコンポーネント）に閉じ込め、各コンポーネントはそれを使うだけの状態にする。
- ヘッダーとサイドバーを半透明の浮遊クロームへ変え、コンテンツがその下を流れる構成にする。
- `prefers-reduced-motion` / `prefers-reduced-transparency` / `prefers-contrast` の 3 設定に、CSS と JS の両側で追従する。
- 既存の機能・API・`data-testid` を維持したまま、コンポーネント単位で段階的に移行できる形にする。

**Non-Goals:**

- 狭幅ウィンドウ・モバイル Web 向けのレスポンシブレイアウト設計（現状の `min-w-[800px]` 前提は維持する）。別変更として扱う。
- Flutter モバイルアプリ（`mobile/`）の意匠更新。本変更中は Web/Electron と乖離する。
- バックエンド、API スキーマ、認証フロー、データモデルの変更。
- UI コンポーネントライブラリの全面導入（Radix 一式の追加など）。必要な最小限に留める。
- 触覚・音によるフィードバックの追加。
- 情報設計・画面遷移そのものの再設計。既存の 3 ペイン構成と操作フローは維持する。

## Decisions

### 1. モーションライブラリは `motion`（v13）を採用する

**選定理由**: 仕様が要求する「中断時に現在の描画値から継続」「反転時に速度を引き継ぐ」「解放速度を初速として渡す」は、CSS トランジションおよび `@keyframes` では原理的に満たせません（目標値からの再開になり、跳躍と速度の不連続が生じます）。`motion` はバネを第一級で扱い、再ターゲット時に現在値と速度を引き継ぎ、`velocity` を初速として受け取れます。React 19 を peer dependency に含み（`react: ^18 || ^19`）、`AnimatePresence` により退出アニメーションを扱えます。

**代替案**:
- *CSS トランジション + `@starting-style`/`transition-behavior: allow-discrete`*: 出入りの記述は簡潔になりますが、中断・反転・速度引き継ぎを満たせないため、ジェスチャを伴う要素には不適です。ジェスチャを伴わない純粋な色変化（ホバー、フォーカスリング）にのみ引き続き CSS を使います。
- *`requestAnimationFrame` による自作バネ*: 依存を増やさずに済みますが、速度の引き継ぎ・再ターゲット・退出制御を自前で保守することになり、割に合いません。
- *`react-spring`*: 要件は満たせますが、Apple の damping/response と対応付けやすい `bounce`/`duration` API を持つ `motion` の方が、仕様の数値をそのまま表現できます。

**バンドルへの影響**: `motion/react` の追加は数十 KB 規模ですが、既に `mermaid` と `shiki` を同梱しているため相対的な増分は小さく、これらは既に遅延読み込み対象です。実測は移行完了時に `vite build` の出力で確認します。

### 2. バネのパラメータをトークン化する（`src/lib/motion/springs.ts`）

Apple の damping / response を `motion` の `bounce` / `duration` へ対応付け、名前付きプリセットとして 1 箇所に定義します。個々のコンポーネントが生の数値を書くことを禁止します。

| プリセット | 用途 | damping / response | `motion` 指定 |
| --- | --- | --- | --- |
| `snap` | 既定。位置・サイズの移動、面の出現 | 1.0 / 0.35 | `{ type: 'spring', bounce: 0, duration: 0.35 }` |
| `sheet` | シート・パネルの出入り | 0.8 / 0.3 | `{ type: 'spring', bounce: 0.2, duration: 0.3 }` |
| `momentum` | ドラッグ解放後の着地 | 0.8 / 0.4 | `{ type: 'spring', bounce: 0.2, duration: 0.4, velocity }` |

**根拠**: 既定を臨界減衰（`bounce: 0`）に固定することで、勢いを伴わない出現にバウンスが混ざる典型的な失敗を構造的に防げます。バウンスは `momentum` / `sheet` を明示的に選んだ箇所にしか現れません。

### 3. トークン層は既存の Tailwind v4 パターンを拡張する（作り直さない）

`:root` / `.dark` に CSS 変数、`@theme inline` で Tailwind ユーティリティへ写像する現行の構成を維持し、そこへ層を追加します。

- **色**: 値の表記を `hsl()` から `oklch()` へ移行します。既存ファイルは既に完全な関数形式（`hsl(222.2 84% 4.9%)`）で値を保持しているため、`@theme inline` 側の写像を変更せずに置換できます。知覚的に均一な明度を持つ `oklch` により、ライト/ダークで同じコントラスト感を保つ調整が現実的になります。既定 slate のニュートラルは暖色寄りへ置き換えます。一方でアクセントの色相は、現行の青（ライト `hsl(221.2 83.2% 53.3%)` / ダーク `hsl(217.2 91.2% 59.8%)`）を PostAll のブランド色としてそのまま維持し、oklch へ変換したうえでライト/ダーク間の彩度と明度のみを揃えます。
- **タイポグラフィ**: サイズごとに「サイズ・行間・字間」を三つ組で定義します（`--text-display` / `--leading-display` / `--tracking-display` …）。大きい段ほど字間を負に、行間を狭くします。本文の字間は 0 付近に据えます。フォントは Apple の指針どおりシステムフォント（`system-ui`, `-apple-system`）を継続し、Web フォントは追加しません。余白は `rem` を基準にし、利用者の文字サイズ設定に追従させます。
- **エレベーションと材質**: `--shadow-{sm,md,lg}` と `--material-{thin,regular,thick}`（背景色 + `backdrop-filter` の組）を定義します。面の大きさと材質の重さを対応付けます。

**代替案**: shadcn の新しい既定テーマをそのまま取り込む案は、再び「初期設定のまま」の見た目になるため採りません。トークンの構造だけを踏襲し、値は自前で決めます。

### 4. 操作プリミティブを 3 つのフックに集約する

ジェスチャの細部（ヒステリシス、グラブオフセット、速度履歴、投影、抵抗）を各コンポーネントに散らさず、次に閉じ込めます。

- `usePressable()` — pointer-down で押下状態を立て、範囲外への離脱で解除、復帰で再度立て、pointer-up で確定。約 10px のヒットパディングを含みます。既存の `<button>` 群と `ChannelTree` の行、`ReactionBar` のチップに適用します。
- `useDragValue()` — `setPointerCapture` による追従、グラブオフセットの保持、直近数フレームの位置と時刻から解放速度を算出、境界外はラバーバンディング（`overshoot * d * c / (d + c * |overshoot|)`、`c = 0.55`）、解放時は減速の指数モデル `current + (v/1000) * d / (1 - d)`（`d = 0.998`）で停止位置を予測してから吸着先を決め、その速度を `momentum` プリセットの初速として渡します。サイドバー境界に適用し、将来のシート系にも再利用します。
- `useOverlayPresence()` — `<dialog>` の `showModal()` / `close()` と `AnimatePresence` の橋渡し。

起動元を原点とする出現・退出（`fluid-interactions` の「出入りの経路は対称で出現元にひも付く」）については、独立したラッパーコンポーネントを作りません。決定 5 のとおりモーダル系はすべて中央配置となり、起動元にアンカーされる面は `ReactionBar` のツールチップだけになるため、`transform-origin` の指定と `snap` プリセットを当該スタイルへ直接記述します。ポップオーバーが増えた時点で共通化を検討します。

**根拠**: 仕様のジェスチャ要件はすべて「同じ 1 本の実装が正しいか」に帰着します。プリミティブに集約すれば単体テストの対象が 2 フックで済み、各コンポーネントのレビュー対象は見た目だけになります。

### 5. オーバーレイをネイティブ `<dialog>` に一本化する

現状のオーバーレイは実装が二系統に分かれています。`SearchDialog.tsx` と `SettingsDialog.tsx` はネイティブ `<dialog>` + `showModal()` を使う一方、`EmojiPicker.tsx` と `PostActions.tsx` の確認ダイアログは `createPortal` + `fixed inset-0` に、Tab の巡回を自前で組んだフォーカストラップと Escape ハンドラを添えた実装です。本変更では後者をネイティブ `<dialog>` へ寄せ、自前のフォーカストラップを削除します。

**根拠**: `showModal()` はフォーカストラップ、トップレイヤー、背景の不活性化、Esc による閉鎖を無償で提供します。加えて、退出アニメーションの橋渡し（`useOverlayPresence()`）を二系統ぶん書かずに 1 本で済ませられます。一本化は正味のコード削減であり、モーション導入の前提でもあります。

退出アニメーションは、閉じる要求を受けても即 `close()` せず、`AnimatePresence` の退出完了コールバックで `close()` を呼ぶ形にします。閉じる途中に再度開く要求が来た場合は `AnimatePresence` が現在値から反転するため、`close()` は呼ばれません。

**代替案**:
- *二系統を維持したまま橋渡しを二種類用意する*: 変更範囲は小さく見えますが、中断・反転の正しさを二箇所で担保することになり、総量では増えます。
- *`@starting-style` + `allow-discrete` による CSS のみの実装*: 記述量は少ない一方、閉じる途中での再オープンが跳躍します。仕様の「中断・反転」要件に反するため採りません。

**留意点**: これは見た目に留まらない変更であり、`EmojiPicker` と `PostActions` のフォーカス挙動に関する既存テストの更新が必要になります。挙動の互換性（Esc で閉じる、閉じた後に起動元へフォーカスが戻る）は維持します。

### 6. スクロールエッジ効果は重なりが生じる箇所にのみ適用する

ヘッダー下の `border-b` を廃し、スクロール領域の先頭にセンチネル要素を置いて `IntersectionObserver` で「コンテンツがクロームに潜り込んでいるか」を判定し、潜り込んでいる間だけ上端のマスク（グラデーション）と材質の厚みを強めます。スクロール位置を `scroll` イベントで毎フレーム読む実装は避けます。

### 7. アクセシビリティ設定は CSS と JS の二経路で扱う

- `prefers-reduced-transparency` と `prefers-contrast` は純粋に見た目の問題であり、`index.css` のメディアクエリで材質トークンを不透明側・高コントラスト側へ差し替えます。
- `prefers-reduced-motion` は JS 側でも必要です（バネの生成を抑止するため）。ルート近くに `<MotionConfig reducedMotion="user">` を置き、加えて `useReducedMotion()` を参照するプリミティブ側で、移動・拡大を伴う演出を短いクロスフェードへ差し替えます。押下・完了・エラーのフィードバック自体は残します。

### 8. 既存の検証を壊さない移行の作法

- `data-testid` は追加のみ行い、削除・改名しません。
- Playwright は `playwright.config.ts` のコンテキストに `reducedMotion: 'reduce'` を設定し、E2E をアニメーションから独立させます。これによりモーション由来のフレークを構造的に排除します。モーション自体の検証は、プリミティブの単体テストで行います。
- Vitest（jsdom）では `Element.animate` が存在しないため、`setup` で `MotionGlobalConfig.skipAnimations = true` 相当の設定を行い、コンポーネントテストを最終状態で評価します。

## Risks / Trade-offs

- **[`backdrop-filter` を敷いた面の上で大量のコンテンツがスクロールすると描画コストが上がる]** → 材質はヘッダー・サイドバー・オーバーレイのクローム層に限定し、タイムラインの行やポストには適用しません。ぼかし半径のアニメーションは面の出入り時のみとし、スクロール中は変化させません。Electron/Chromium の実機で、長いタイムラインのスクロールを目視とフレーム計測で確認します。
- **[パレットを oklch へ全面移行する際にコントラストが劣化する]** → 移行時にライト/ダーク双方で、本文・補助テキスト・無効状態・境界・フォーカスリングのコントラスト比を実測し、下回る組み合わせを個別に補正します。トークン層に閉じているため、補正はコンポーネントに波及しません。
- **[ジェスチャの中断・反転はコードを読むだけでは正しさを判定しにくい]** → 実装を `useDragValue()` に集約し、速度算出・投影・ラバーバンディングを純粋関数として切り出して単体テストを書きます。中断・反転の挙動はブラウザ上でコマ送りに近い確認を行います。
- **[既存の Vitest / Playwright が DOM 構造とクラス名の変更で落ちる]** → `data-testid` を維持し、コンポーネント単位で移行して各段階でテストを実行します。落ちたテストは、意図した変更を反映する形で更新します。
- **[`motion` 追加によるバンドル増]** → 移行完了時に `vite build` の出力サイズを移行前後で比較し、増分を記録します。許容できない場合は、オーバーレイ系のみ動的インポートへ切り替えます。
- **[Flutter モバイルアプリとの意匠の乖離]** → 本変更では受け入れます。確定したトークン値（色・字送り・角丸・バネのパラメータ）を `design.md` と実装に残し、後続のモバイル側変更が同じ値を参照できる状態にします。

## Migration Plan

視覚のみの変更であり、機能フラグもデータ移行も伴わないため、段階ごとに `main` へマージ可能です。

1. **トークン層**: `index.css` を刷新し、色・タイポグラフィ・エレベーション・材質のトークンを定義。既存コンポーネントは新しいトークンを参照するだけで見た目が更新される。
2. **プリミティブ**: `motion` を追加し、`springs.ts` と 3 フックを単体テスト付きで実装。この時点では利用箇所なし。
3. **クローム**: `AppShell` のヘッダー・サイドバー・境界ドラッグを移行（`desktop-shell` の変更要件に対応）。
4. **オーバーレイ**: 検索・設定・絵文字ピッカー・スレッドパネル。
5. **行と操作要素**: `ChannelTree`、`Timeline`、`PostActions`、`ReactionBar`、`Composer`、`UpdateBanner`、`SignInScreen`。
6. **仕上げ**: アクセシビリティ 3 設定の確認、コントラスト実測、バンドルサイズ比較。

**ロールバック**: 各段階は独立したコミットであり、該当コミットの revert で戻せます。データもスキーマも変わらないため、ロールバックに伴う移行作業はありません。

## Open Questions

**解決済み**（2026-08-28、提案者の回答による）:

- *アクセント色の色相*: 現行の青を PostAll のブランド色として維持します。表記を oklch へ変換し、置き換えるのはニュートラルのみとします（決定 3）。
- *絵文字ピッカーの形式*: 起動元にアンカーされたポップオーバーとはせず、中央配置のモーダルのままとします。ただし実装はネイティブ `<dialog>` へ統一します（決定 5）。

**未解決**:

- タイムラインの検索結果ジャンプ時に、着地したポストを一時的に強調する演出を加えるかどうか（`post-timeline` の要件追加になるため、加える場合は本変更ではなく別変更とします）。
