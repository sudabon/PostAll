## ADDED Requirements

### Requirement: デザイントークンの単一定義
システムは、配色・タイポグラフィ・余白・角丸・エレベーション（影）・材質（半透明レイヤー）の値を、単一のトークン定義から供給しなければならない (SHALL)。UI コンポーネントは、これらの視覚的な値をトークン参照としてのみ記述しなければならない (SHALL)。個別のコンポーネントが色・影・角丸のリテラル値を直接記述してはならない (MUST NOT)。

#### Scenario: コンポーネントがトークンを参照する
- **WHEN** コンポーネントが背景色・文字色・境界色・影・角丸を指定する
- **THEN** システムはトークン経由で値を解決し、コンポーネント側にリテラルの色値や影の定義を持たない

#### Scenario: トークンの変更が全画面へ波及する
- **WHEN** トークン定義において基準となる値（例: 主要色、基準角丸）を変更する
- **THEN** システムは当該トークンを参照するすべての画面へ変更を反映し、個別のコンポーネント修正を必要としない

#### Scenario: 用途のないトークンを持たない
- **WHEN** トークン体系を定義する
- **THEN** システムは実際に UI で使用される用途に対応するトークンのみを定義し、未使用のトークンを残さない

### Requirement: サイズ別のタイポグラフィ
システムは、文字サイズごとに字間（トラッキング）と行間（リーディング）を定めなければならない (SHALL)。大きな見出しでは字間を詰め行間を狭く、本文では字間を標準的に保ち行間を広く取らなければならない (SHALL)。すべての文字サイズに単一の字間値を適用してはならない (MUST NOT)。

#### Scenario: 見出しと本文で字間・行間が異なる
- **WHEN** 画面に見出しと本文が同時に表示される
- **THEN** システムは見出しに詰めた字間と狭い行間を、本文に標準的な字間と広い行間を適用する

#### Scenario: 階層を太さとサイズの組で表現する
- **WHEN** 同一画面内で情報の重要度に差を付ける
- **THEN** システムは文字サイズ・太さ・行間の組み合わせで階層を表現し、サイズのみに依存しない

#### Scenario: 文字サイズ設定を拡大しても崩れない
- **WHEN** 利用者がブラウザまたは OS の文字サイズ設定を拡大する
- **THEN** システムは余白と行の高さを文字サイズに追従して拡大し、要素の重なりや文字の切れを起こさない

### Requirement: 材質による階層表現
システムは、ナビゲーション・ツールバー・シート・ポップオーバーなどの浮遊するクロームを、コンテンツがその下を流れる半透明の材質レイヤーとして表現しなければならない (SHALL)。材質の重さは階層に対応させ、構造を区切る面には重い材質を、操作要素には軽い材質を用いなければならない (SHALL)。軽い半透明の面を別の半透明の面の上に重ねてはならない (MUST NOT)。

#### Scenario: コンテンツがクロームの下を流れる
- **WHEN** 利用者がタイムラインをスクロールする
- **THEN** システムはヘッダーを半透明の浮遊レイヤーとして保ち、その背後をコンテンツが通過する見え方を維持する

#### Scenario: 面の大きさに応じた厚み
- **WHEN** 大きな面（ダイアログ、サイドバー）と小さな面（チップ、ツールチップ）を同時に表示する
- **THEN** システムは大きな面により強いぼかしと深い影を、小さな面により弱いぼかしと浅い影を与える

#### Scenario: 重なる箇所だけを縁取る
- **WHEN** 浮遊するクロームとコンテンツが重なる
- **THEN** システムは当該の境目にのみスクロールエッジ効果（ぼかし・グラデーションによる減衰）を適用し、常時表示の 1px 境界線を用いない

#### Scenario: 集中を要する操作は背景を沈める
- **WHEN** 利用者が操作を占有するモーダル（検索、設定）を開く
- **THEN** システムは背景を暗転させて後退させ、モーダル以外への操作を受け付けない

#### Scenario: 並行して使う面は流れを断たない
- **WHEN** 利用者がスレッドパネルのような並行して参照する面を開く
- **THEN** システムは暗転させずに半透明とオフセットで前後関係を示し、タイムラインの操作を継続可能に保つ

### Requirement: ライトテーマとダークテーマの同等品質
システムは、すべてのトークンについてライトとダークの両方の値を定義しなければならない (SHALL)。いずれのテーマにおいても、本文・補助テキスト・境界・フォーカス表示のコントラストが判読可能な水準を下回ってはならない (MUST NOT)。

#### Scenario: 両テーマで判読できる
- **WHEN** 利用者がライトとダークを切り替える
- **THEN** システムはどちらのテーマでも本文・補助テキスト・無効状態・フォーカス表示が判読可能なコントラストを保つ

#### Scenario: 半透明面の上の文字が読める
- **WHEN** 半透明の面の上に文字を表示する
- **THEN** システムは平坦な灰色ではなく、コントラストを高めた色と僅かに太い字面で文字を表示し、背景の変化によらず判読性を保つ

#### Scenario: テーマ切り替えを急激な明滅にしない
- **WHEN** テーマがライトからダーク（またはその逆）へ切り替わる
- **THEN** システムは配色の変化を緩和して適用し、瞬間的な明滅を起こさない

### Requirement: アクセシビリティ設定への追従
システムは、利用者の OS/ブラウザ設定である「透明度を下げる」および「コントラストを上げる」に追従して表示を切り替えなければならない (SHALL)。

#### Scenario: 透明度を下げる設定
- **WHEN** 利用者の環境が透明度低減を要求している
- **THEN** システムは半透明の面の背景を不透明に近づけ、背景のぼかしを無効化する

#### Scenario: コントラストを上げる設定
- **WHEN** 利用者の環境が高コントラストを要求している
- **THEN** システムは面の背景をほぼ不透明にし、明確なコントラストを持つ境界線を付与する

### Requirement: フォーカスと状態表示の一貫性
システムは、フォーカス・ホバー・押下・無効・選択中の各状態を、トークンに基づく一貫した表現で示さなければならない (SHALL)。キーボード操作時のフォーカス位置は常に視認できなければならない (SHALL)。

#### Scenario: キーボードでフォーカスを移動する
- **WHEN** 利用者が Tab キーで操作要素間を移動する
- **THEN** システムは現在フォーカスされている要素を明確に視認できる形で示す

#### Scenario: 同じ意味の状態は同じ見た目
- **WHEN** 異なる画面の同種の操作要素が同じ状態（例: 選択中）になる
- **THEN** システムは同一のトークンに基づく同じ見た目でその状態を示す
