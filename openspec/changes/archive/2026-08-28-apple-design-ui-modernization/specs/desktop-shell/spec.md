## MODIFIED Requirements

### Requirement: 3ペインレイアウト
システムは、左に階層チャネルツリー、右上にポストタイムライン、右下にポスト入力フォームを配置する画面構成を提供しなければならない (SHALL)。画面上部のヘッダーと左のサイドバーは、コンテンツがその背後を流れる半透明の浮遊レイヤーとして表示しなければならない (SHALL)。浮遊レイヤーとコンテンツの境目は、常時表示の境界線ではなく、両者が重なる箇所に限ったスクロールエッジ効果で示さなければならない (SHALL)。

#### Scenario: 既定のレイアウトを表示する
- **WHEN** ユーザーがサインイン済みの状態でアプリを開く
- **THEN** システムは左ペインにチャネルツリー、右ペイン上部にタイムライン、右ペイン最下部に入力フォームを表示する

#### Scenario: コンテンツがヘッダーの下を流れる
- **WHEN** ユーザーがタイムラインをスクロールする
- **THEN** システムはヘッダーを半透明のまま保持し、その背後をコンテンツが通過する見え方を維持したまま、ヘッダー直下にスクロールエッジ効果を適用する

#### Scenario: サイドバーの幅を変更する
- **WHEN** ユーザーが左ペインと右ペインの境界をドラッグする
- **THEN** システムは左ペインの幅をポインタの移動量に 1:1 で追従させ、最小幅と最大幅の範囲で変更し、その幅を永続化する

#### Scenario: サイドバー幅の境界を超えてドラッグする
- **WHEN** ユーザーが最小幅または最大幅を超えて境界をドラッグする
- **THEN** システムは追従を突然止めず、進むほど強まる抵抗を与えながら追従し、解放時に範囲内の境界幅へバネで戻す

#### Scenario: 境界のドラッグを勢いよく解放する
- **WHEN** ユーザーが境界を勢いよく動かして解放する
- **THEN** システムは解放時の速度を引き継いで減速しながら着地させ、解放位置で即座に停止させない

#### Scenario: サイドバーを折りたたむ
- **WHEN** ユーザーがサイドバーの表示切り替え操作を実行する
- **THEN** システムは左ペインを隠し、タイムラインと入力フォームをウィンドウ全幅へ広げる

#### Scenario: 折りたたみと展開が同じ経路をたどる
- **WHEN** ユーザーがサイドバーを折りたたみ、その後展開する
- **THEN** システムは折りたたみ時と展開時で同じ経路の動きを用い、途中で切り替え操作を受け付けても現在の表示位置から反転する

#### Scenario: スレッドパネルを併置する
- **WHEN** ユーザーがスレッドを開く
- **THEN** システムはタイムラインを保持したまま、右側にスレッドパネルを併置し、背景を暗転させずタイムラインの操作を継続可能に保つ

#### Scenario: ウィンドウを縮小する
- **WHEN** ユーザーがウィンドウを最小サイズ付近まで縮小する
- **THEN** システムはレイアウトの崩壊を起こさず、入力フォームを最下部に維持する
