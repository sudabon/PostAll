## Why

コードブロックと箇条書きの入力に、書いている最中に手が止まる摩擦が残っている。

**コードブロックのカーソルが本文の位置に来ない。** 書式ツールバーの「コードブロック」は雛形を挿入したあと、カーソルを開始フェンスの直後＝言語指定の位置に置く（`frontend/src/lib/fence.ts` の `insertCodeFence`）。だが挿入直後にまず書きたいのはコードそのものであり、毎回カーソルを 1 行下へ動かす操作が要る。言語指定を書くのはコードを書いたあとか、書かないことも多い。

**選択範囲を包むと選択テキストが言語指定欄に入る。** `insertCodeFence(value, start, end)` は選択範囲を開始フェンスと同じ行へ連結するため、``` ```<選択>\n``` ``` という形になる。選択したコードが情報文字列（言語名）として解釈され、コードブロックの中身が空になる。単体テストは選択なしの経路しか検証しておらず、この欠陥は素通りしている。

**バッククォート 3 つを打っても何も起きない。** Markdown に慣れた利用者はツールバーではなくバッククォート 3 つでコードブロックを開こうとする。だが閉じフェンスは自分で打つ必要があり、打つまでの間その本文は未閉フェンス扱いになる。この状態では `isInsideUnclosedFence` により Shift+Enter の送信が抑止されるため、閉じ忘れたまま送信しようとしても反応がないように見える。

**箇条書きの入れ子が手入力でしか作れない。** 入力フォームは Tab を扱っておらず、押すとフォーカスが添付ボタンへ移る。入れ子は自分で空白を数えて字下げするしかない。しかも必要な字下げ量は記法によって違い、数字箇条書き（`1. `）を 2 つの空白で字下げすると入れ子にならず別のリストに分裂する。この規則は書いている本人からは見えない。

## What Changes

- コードブロックの雛形を挿入したとき、カーソルを**フェンスに囲まれた本文の行**に置く。書式ツールバーのボタンと、後述のバッククォート自動展開で共通の挙動にする
- 選択範囲を包むときも、選択テキストを本文の行へ移す（言語指定欄に入る欠陥の修正）
- **行頭でバッククォートを 3 つ連続して入力したら、フェンス付きコードブロックへ自動展開する。** 未閉のコードブロックの中、貼り付け、IME 変換中は展開しない
- **箇条書きの行で Tab をインデント、Shift+Tab をその逆操作（インデント解除）に割り当てる。** Tab の直後の Shift+Tab は本文を押す前の状態に戻す。箇条書き以外の行では Tab も Shift+Tab も従来どおりフォーカスを移す
- 書式ツールバーの箇条書き・引用が、インデントされた行でもインデントを保ったままマーカーを切り替えるようにする
- **BREAKING なし**（API・データモデル・保存される本文の書式に変更はない。Markdown として従来どおり解釈できるテキストしか生成しない）

## Capabilities

### New Capabilities

なし。既存 capability の要件変更のみ。

### Modified Capabilities

- `post-composer`: 「コードブロック入力の補助」を、雛形挿入後のカーソル位置・選択範囲の扱い・バッククォート 3 連続での自動展開を含む形に変更する。あわせて「箇条書きのインデント操作」を新しい要件として追加する

## Impact

**フロントエンドのみ。** バックエンド・API・DB スキーマの変更はない。依存関係の追加もない。

| 対象 | 内容 |
|---|---|
| `frontend/src/lib/fence.ts` | `insertCodeFence` のカーソル位置と選択範囲の扱いを変更する。バッククォート 3 連続を検出する `expandFenceTrigger` を追加する |
| `frontend/src/lib/markdown-format.ts` | 箇条書き行のインデント増減 `indentLines` を追加する。`anyLineMarker` と `applyLinePrefix` を先頭インデント保持に対応させる |
| `frontend/src/components/composer/Composer.tsx` | textarea の `onChange` で自動展開、`onKeyDown` で Tab / Shift+Tab を扱う |
| `frontend/src/lib/fence.test.ts` | 既存の期待値を更新し、選択範囲・自動展開の単体テストを追加する |
| `frontend/src/lib/markdown-format.test.ts` | 既存の期待値を更新し、`indentLines` とインデント付き行の書式適用を追加する |
| `frontend/src/components/composer/Composer.test.tsx` | 自動展開と Tab の結合テストを追加する |

**アクセシビリティの制約**: Tab は textarea から抜ける唯一のキーボード手段である。このアプリは送信が Shift+Enter なので Enter でも抜けられない。Tab を無条件にインデントへ割り当てると WCAG 2.1.2（キーボードトラップ）に該当するため、**箇条書きの行に限って**奪う。
