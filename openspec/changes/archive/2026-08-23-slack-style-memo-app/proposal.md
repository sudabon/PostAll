## Why

メモは「あとで整理する」前提で書くと結局整理されない。Slack のようにチャネルへ放り込むだけで時系列に積み上がり、後から階層で束ね直せる形なら、書く瞬間のコストをゼロに近づけたまま構造を育てられる。PostAll はこの「ポスト型メモ」を macOS デスクトップ、ブラウザ（PWA）、iOS の 3 経路で成立させることを狙う。現在リポジトリは README のみで実装が存在しないため、本 change がプロダクトの最初の骨格となる。

## What Changes

- **Go バックエンド API** を新設する。インターネット上のコンテナサーバで稼働し、PostgreSQL を永続化層として、全クライアントへ同一のデータを提供する単一の source of truth となる。
- **Nginx と Certbot をコンテナとして配備**する。Nginx が TLS 終端かつ唯一の公開エンドポイントとなり、API と PWA へ振り分ける。Certbot が証明書を取得し自動更新する。
- **AWS Cognito ユーザープールによる認証**を導入する。全 API は認証済みの要求のみを受理する。
- **3ペイン構成のフロントエンド**（React + TypeScript + Vite + TailwindCSS + shadcn/ui）を新設し、**Electron によるデスクトップアプリ**と**ブラウザ向け PWA** の 2 経路で配布する。左ペイン=チャネルツリー、右ペイン上部=当該チャネルのポスト一覧（古い順）、右ペイン最下部=固定のポスト入力フォーム。
- **Flutter による iOS アプリ**を新設する。狭幅では 3 ペインを「チャネル一覧 → タイムライン」の階層ナビゲーションに畳み、入力フォームは画面下部に固定する。
- **階層チャネル**を導入する。チャネルは親子関係を持ち、階層の深さに上限を設けない。ツリー上の drag & drop（iOS ではロングプレスドラッグ）で親の付け替え／並び順の変更ができる。
- **ポストの投稿・編集・削除**を提供する。1 ポスト = 1 メモ。削除は論理削除とし、編集履歴は保持しない。タイムラインは古い順に並び、初期表示は最新 10 件、上方向スクロールで過去を動的に取得する。
- **スレッド返信**を提供する。ポストに対する返信をスレッドとしてぶら下げ、専用ビューで読み書きできる。
- **絵文字リアクション**を提供する。`emoji/` ディレクトリに配置した png をカスタム絵文字として登録し、ポストへのリアクションとして使う。
- **リッチコンテンツ描画**を提供する。Markdown、コードブロック（言語別シンタックスハイライト）、および `mermaid` 指定のコードブロックの図としての描画（投稿確定時に描画し、入力中のライブプレビューは行わない）。
- **添付**を提供する。実体は S3 バケットに保存し、署名付き URL でアップロード／ダウンロードする。画像はインライン表示、その他ファイルは添付カードとして表示する。
- **全文検索**を提供する。PostgreSQL 拡張 `pg_bigm` により、日本語を含むポスト本文を横断検索する。
- 全クライアントは**オンライン動作を前提**とする。オフラインでの編集・投稿キューは本 change のスコープに含めない。

いずれも新規追加であり、既存の破壊的変更（**BREAKING**）は無い（既存実装が存在しないため）。

## Capabilities

### New Capabilities

- `authentication`: AWS Cognito ユーザープールによるサインイン、トークンの保持と更新、失効時の再認証、全 API 要求への認可付与。
- `channel-hierarchy`: チャネルの作成・リネーム・削除、親子階層の表現（深さ上限なし・同一階層での同名禁止・ポストを持つチャネルの削除禁止）、drag & drop による階層と並び順の編集、展開／折りたたみ状態の保持。
- `post-timeline`: 選択中チャネルのポストを古い順に一覧表示する。初期表示は最新 10 件、上方向スクロールでの動的な過去取得、ポストの編集と論理削除、投稿直後の反映。
- `post-composer`: タイムライン最下部に固定される投稿フォーム。複数行入力、下書き保持、送信操作、添付の追加、コードブロック入力の補助、スレッドへの返信投稿。
- `post-threads`: ポストへの返信スレッド。スレッドビューでの返信の閲覧と投稿、親ポストへの返信件数表示、スレッド内ポストの編集・削除。
- `emoji-reactions`: `emoji/` ディレクトリの png をカスタム絵文字として登録するカタログ、ポストへのリアクション付与・解除、リアクション一覧と件数の表示。
- `rich-content-rendering`: ポスト本文の Markdown 描画、コードブロックのシンタックスハイライト、`mermaid` コードブロックの図描画（投稿確定時）とレンダリング失敗時のフォールバック。
- `attachments`: 画像／ファイルの添付、S3 への署名付きアップロード、署名付き URL でのダウンロード、一覧・プレビュー表示、削除、サイズと形式の制約。
- `full-text-search`: `pg_bigm` によるポスト本文の全文検索、チャネル絞り込み、検索結果からのポストへの移動。
- `desktop-shell`: Electron による macOS デスクトップアプリの外殻。ウィンドウ、3ペインレイアウトとリサイズ、キーボードショートカット、アプリメニュー、起動時の状態復元。
- `pwa-delivery`: ブラウザ向け PWA としての配信。インストール可能性、アプリシェルのキャッシュ、Electron 固有機能のブラウザ API へのフォールバック。
- `mobile-shell`: Flutter による iOS アプリの外殻。狭幅でのナビゲーション構造、ソフトキーボードと入力フォームの共存、タッチ操作でのチャネル階層編集。
- `sync-and-storage`: Go バックエンドの PostgreSQL データモデルと API 契約、変更の反映、オンライン前提での接続断時の振る舞い。
- `deployment`: Nginx / Certbot / API サーバ / PostgreSQL のコンテナ構成、TLS 終端とリバースプロキシの振り分け、証明書の取得と自動更新、データの永続化、マイグレーション適用、ヘルスチェック。

### Modified Capabilities

（なし。`openspec/specs/` は空であり、既存 capability の要件変更は発生しない）

## Impact

- **リポジトリ全体**: 実装コードが 0 の状態から、Go バックエンド／React フロントエンド（Electron + PWA）／Flutter iOS の成果物を含むモノレポ構成が新規に追加される。ディレクトリ構成、パッケージマネージャ、テスト基盤、CI もこの change で確定する。
- **技術スタック（確定）**:
  - バックエンド: Go / PostgreSQL（`pg_bigm` 拡張）
  - 認証: AWS Cognito ユーザープール
  - ファイルストレージ: Amazon S3
  - デスクトップ・Web: React + TypeScript + Vite + TailwindCSS + shadcn/ui、Electron および PWA の 2 配布経路
  - モバイル: Flutter（iOS のみ）
  - 実行環境: インターネット上のコンテナサーバ（Nginx / Certbot / API サーバ / PostgreSQL をコンテナとして配備）
- **インフラ**: AWS アカウント上に Cognito ユーザープール、S3 バケットが新規に必要になる。サーバ側には Nginx（TLS 終端・リバースプロキシ）、Certbot（証明書の取得と自動更新）、API サーバ、PostgreSQL のコンテナ構成と、独自ドメインが要る。
- **外部依存**: Markdown パーサ、シンタックスハイライタ、Mermaid、drag & drop ライブラリ（React 側）、Flutter 側の対応パッケージ、Go 側の PostgreSQL ドライバ・マイグレーションツール・AWS SDK が新規依存として入る。
- **API 契約**: 3 つのクライアント（Electron / PWA / iOS）が同一 API を共有するため、エンドポイント・スキーマ・エラー形式がここで固定される。
- **運用**: コンテナのデプロイ、TLS 証明書の自動更新の監視、PostgreSQL のバックアップとマイグレーション適用、S3 のライフサイクル、Cognito のユーザー管理が新たに発生する。
- **データ**: チャネル階層・ポスト・スレッド・リアクションのスキーマがここで固定されるため、後続 change での移行コストに直結する。
- **配布**: macOS アプリの署名・公証、PWA のホスティング、iOS アプリのストア配布要件が新たに発生する。

## Open Questions

初回の Open Questions 13 件はすべて回答済みで、決定内容は `design.md` の Decisions に反映済み。以下は、その決定から新たに派生した未決事項。

1. **PostgreSQL の運用形態** (M0): 自前コンテナで動かすか、Amazon RDS を使うか。**`pg_bigm` は RDS for PostgreSQL では利用可能だが、Aurora PostgreSQL では提供されていない。** RDS を選ぶ場合は対応バージョンの確認が必要で、Aurora を選ぶ場合は全文検索方式の再検討（`pg_trgm` または別手段）が発生する。
2. **コンテナのホスト** (M0/M9): Nginx / Certbot / API / PostgreSQL のコンテナ一式を動かすホストをどこに置くか（EC2 / VPS / 他）。オーケストレーションは Docker Compose で足りるか。独自ドメインの取得と DNS の管理主体。
3. **Cognito の認証 UI** (M1): Hosted UI を使うか、各クライアントでカスタムのサインイン画面を作るか。Electron / PWA / iOS でそれぞれ認可コードフローをどう扱うか（リダイレクト URI の設計）。
4. **AWS リソースの構築手段** (M0): IaC（Terraform / CDK）で管理するか、初期は手動構築とするか。
5. **S3 の公開方式** (M5): 署名付き URL で直接 S3 へアクセスするか、CloudFront を挟むか。バケットのライフサイクルポリシー（論理削除されたポストの添付をいつ物理削除するか）。
6. **論理削除されたポストの表示** (M2): タイムライン上に「削除されました」のプレースホルダを残すか、完全に非表示にするか。スレッド返信を持つポストが削除された場合の親子関係の扱い。
7. **スレッド返信のチャネル表示** (M3): Slack の「チャネルにも投稿する」に相当する機能が必要か。不要なら、スレッド返信はチャネルのタイムラインに一切出さない。
8. **絵文字カタログの登録方法** (M6): `emoji/` ディレクトリの png をいつ DB へ登録するか（サーバ起動時の自動走査 / 管理コマンドの明示実行 / デプロイ時のジョブ）。Unicode 標準絵文字も併用できるようにするか、カスタム png のみとするか。
9. **絵文字 png の配信経路** (M6): 静的アセットとしてバックエンドから配信するか、S3 へアップロードして配信するか。
10. **検索のスコープと表示** (M7): 検索対象を本文のみとするか、チャネル名やファイル名も含めるか。結果からポストへ移動したときのタイムラインの表示位置。
11. **PWA のオフライン範囲** (M4): オンライン前提のため、Service Worker がキャッシュするのはアプリシェル（HTML/JS/CSS）のみでよいか、直近のデータもキャッシュするか。
12. **iOS での PWA 利用** (M6): Flutter アプリがあるため、iOS Safari からの PWA インストールは想定しなくてよいか。
13. **チャネルのアーカイブ** (スコープ外候補): 「ポストを持つチャネルは削除禁止」の代替手段としてアーカイブ機能が将来必要になる。本 change ではデータモデルに `archived_at` を先に用意するか、完全に後続 change へ送るか。
14. **タイムゾーンとロケール** (M2/M3): 日付セパレータの区切りをどのタイムゾーンで判定するか。UI 文言は日本語のみか、多言語化の余地を持つか。
