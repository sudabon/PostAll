## ADDED Requirements

### Requirement: Electron による macOS アプリ
システムは、Electron を用いて macOS 上で独立したデスクトップアプリケーションとして起動できなければならない (SHALL)。フロントエンドの成果物をローカルに同梱し、起動時にネットワークからの取得を待たずに画面を表示できなければならない (SHALL)。

#### Scenario: アプリを起動する
- **WHEN** ユーザーが macOS 上で PostAll を起動する
- **THEN** システムはアプリケーションウィンドウを表示し、同梱された成果物から画面を描画する

#### Scenario: バックエンドへ接続できない
- **WHEN** アプリ起動時にバックエンド API へ接続できない
- **THEN** システムは接続できない旨と再試行手段を提示し、空白画面のまま放置しない

#### Scenario: 未サインイン状態で起動する
- **WHEN** 認証情報を持たない状態でアプリを起動する
- **THEN** システムはサインイン画面を表示する

### Requirement: プラットフォーム機能はアダプタ経由で呼び出す
システムは、Electron 固有の機能（アプリメニュー、グローバルショートカット、ネイティブダイアログ、OS 通知、安全な資格情報保管）を、プラットフォームアダプタのインターフェース越しにのみ呼び出さなければならない (SHALL)。UI コンポーネントが Electron 固有 API を直接参照してはならない (MUST NOT)。

#### Scenario: アダプタ経由で機能を使う
- **WHEN** 画面がネイティブのファイル保存ダイアログを必要とする
- **THEN** システムはプラットフォームアダプタの操作を呼び出し、Electron 固有 API を画面から直接参照しない

#### Scenario: 同じコードがブラウザでも動く
- **WHEN** 同一のフロントエンドコードをブラウザで実行する
- **THEN** システムは Electron 固有 API の不在によって実行時エラーを起こさない

### Requirement: 3ペインレイアウト
システムは、左に階層チャネルツリー、右上にポストタイムライン、右下にポスト入力フォームを配置する画面構成を提供しなければならない (SHALL)。

#### Scenario: 既定のレイアウトを表示する
- **WHEN** ユーザーがサインイン済みの状態でアプリを開く
- **THEN** システムは左ペインにチャネルツリー、右ペイン上部にタイムライン、右ペイン最下部に入力フォームを表示する

#### Scenario: サイドバーの幅を変更する
- **WHEN** ユーザーが左ペインと右ペインの境界をドラッグする
- **THEN** システムは左ペインの幅を最小幅と最大幅の範囲で変更し、その幅を永続化する

#### Scenario: サイドバーを折りたたむ
- **WHEN** ユーザーがサイドバーの表示切り替え操作を実行する
- **THEN** システムは左ペインを隠し、タイムラインと入力フォームをウィンドウ全幅へ広げる

#### Scenario: スレッドパネルを併置する
- **WHEN** ユーザーがスレッドを開く
- **THEN** システムはタイムラインを保持したまま、右側にスレッドパネルを併置する

#### Scenario: ウィンドウを縮小する
- **WHEN** ユーザーがウィンドウを最小サイズ付近まで縮小する
- **THEN** システムはレイアウトの崩壊を起こさず、入力フォームを最下部に維持する

### Requirement: ウィンドウ状態の復元
システムは、ウィンドウのサイズ・位置、サイドバー幅、選択中チャネル、チャネルの展開状態を保存し、次回起動時に復元しなければならない (SHALL)。

#### Scenario: 再起動後に状態を復元する
- **WHEN** ユーザーがアプリを終了して再度起動する
- **THEN** システムは前回のウィンドウサイズ・位置・サイドバー幅・選択チャネル・展開状態を復元する

### Requirement: キーボードショートカット
システムは、主要操作に対する macOS 慣用のキーボードショートカットを提供しなければならない (SHALL)。

#### Scenario: 入力フォームへフォーカスする
- **WHEN** ユーザーが入力フォームへのフォーカス用ショートカットを押す
- **THEN** システムは入力フォームへフォーカスを移し、カーソルを末尾に置く

#### Scenario: 新規チャネルを作成する
- **WHEN** ユーザーが新規チャネル作成のショートカットを押す
- **THEN** システムはチャネル作成の入力状態を開始する

#### Scenario: 検索を開く
- **WHEN** ユーザーが検索のショートカットを押す
- **THEN** システムは検索の入力状態を開始する

#### Scenario: チャネル間を移動する
- **WHEN** ユーザーがチャネル移動のショートカットを押す
- **THEN** システムはチャネルツリー上の選択を次または前のチャネルへ移し、タイムラインを更新する

#### Scenario: テキスト入力中はショートカットを奪わない
- **WHEN** ユーザーが入力フォームでテキストを編集している
- **THEN** システムはコピー・ペースト・取り消しなど標準のテキスト編集ショートカットを妨げない

### Requirement: アプリケーションメニュー
システムは、macOS のメニューバーに標準的なアプリケーションメニューを提供しなければならない (SHALL)。

#### Scenario: 標準メニューを表示する
- **WHEN** アプリがフォアグラウンドにある
- **THEN** システムはアプリ名メニュー、編集メニュー、表示メニュー、ウィンドウメニューを含むメニューバーを表示する

#### Scenario: 設定を開く
- **WHEN** ユーザーがメニューから設定を開く
- **THEN** システムは接続先やテーマなどのアプリ設定画面を表示する

#### Scenario: サインアウトする
- **WHEN** ユーザーがメニューからサインアウトを実行する
- **THEN** システムはトークンを破棄し、サインイン画面へ戻る

### Requirement: テーマの切り替え
システムは、ライトテーマとダークテーマ、および OS 設定への追従を選択できるようにしなければならない (SHALL)。

#### Scenario: OS のダークモードに追従する
- **WHEN** テーマ設定が「システムに従う」であり、macOS の外観がダークへ切り替わる
- **THEN** システムはアプリの配色をダークテーマへ切り替える

### Requirement: 表示中データの自動更新
システムは、他クライアントでの変更を表示中の画面へ反映しなければならない (SHALL)。

#### Scenario: 他端末で追加されたポストを反映する
- **WHEN** iOS アプリから、デスクトップで表示中のチャネルへポストが追加される
- **THEN** システムはタイムライン末尾へ当該ポストを追加表示する
