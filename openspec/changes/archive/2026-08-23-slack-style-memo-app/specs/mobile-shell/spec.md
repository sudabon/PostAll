## ADDED Requirements

### Requirement: iOS アプリとしての起動
システムは、Flutter による iOS アプリとして起動し、他のクライアントと同じチャネル・ポスト・添付にアクセスできなければならない (SHALL)。

#### Scenario: アプリを起動する
- **WHEN** ユーザーが iOS 端末で PostAll を起動する
- **THEN** システムはサインイン済みであればチャネル一覧を表示し、前回開いていたチャネルがあればそのタイムラインを復元する

#### Scenario: 未サインイン状態で起動する
- **WHEN** 認証情報を持たない状態でアプリを起動する
- **THEN** システムはサインイン画面を表示し、チャネルやポストの内容を表示しない

#### Scenario: バックエンドへ接続できない
- **WHEN** 起動時にバックエンド API へ接続できない
- **THEN** システムは接続できない旨と再試行手段を表示し、古いデータを最新であるかのように表示しない

### Requirement: 狭幅向けナビゲーション
システムは、狭幅画面において 3 ペインを「チャネル一覧」と「タイムライン」の 2 画面に畳み、階層的に遷移できるようにしなければならない (SHALL)。

#### Scenario: チャネルからタイムラインへ遷移する
- **WHEN** ユーザーがチャネル一覧でチャネルをタップする
- **THEN** システムはタイムライン画面へ遷移し、選択したチャネル名をヘッダーに表示する

#### Scenario: チャネル一覧へ戻る
- **WHEN** ユーザーがタイムライン画面で戻る操作（戻るボタンまたはスワイプ）を行う
- **THEN** システムはチャネル一覧へ戻り、直前に選択していたチャネルを強調表示する

#### Scenario: スレッドを開く
- **WHEN** ユーザーがタイムラインでスレッドを開く
- **THEN** システムはスレッドを独立した画面として表示し、戻る操作でタイムラインへ復帰する

#### Scenario: 横向きや大画面で表示する
- **WHEN** アプリが十分な幅を持つ画面（横向き、大型端末）で表示される
- **THEN** システムはチャネル一覧とタイムラインを並列表示するレイアウトへ切り替える

### Requirement: チャネル階層のタッチ操作
システムは、iOS においてもチャネル階層の展開・折りたたみ、および階層と並び順の変更を行えるようにしなければならない (SHALL)。

#### Scenario: 階層を展開する
- **WHEN** ユーザーが子を持つチャネル行の展開トグルをタップする
- **THEN** システムは子チャネルの表示を切り替える

#### Scenario: 長押しドラッグで移動する
- **WHEN** ユーザーがチャネル行を長押ししてドラッグし、別の位置でドロップする
- **THEN** システムは親の付け替えまたは並び順の変更を適用し、結果を保存する

#### Scenario: 無効な移動を拒否する
- **WHEN** ユーザーがチャネルを自身の子孫へドロップしようとする
- **THEN** システムは移動を適用せず、元の位置へ戻す

#### Scenario: 名前が衝突する移動を拒否する
- **WHEN** ユーザーがチャネルを、同名のチャネルが既に存在する親の配下へドロップする
- **THEN** システムは移動を適用せず、衝突する旨を表示して元の位置へ戻す

### Requirement: ソフトキーボードと入力フォームの共存
システムは、入力フォームを画面最下部に固定し、ソフトキーボード表示時にはフォームがキーボードの上に留まるようにしなければならない (SHALL)。

#### Scenario: キーボードを開く
- **WHEN** ユーザーが入力フォームをタップしてソフトキーボードが表示される
- **THEN** システムは入力フォームをキーボードの直上へ移動させ、隠さない

#### Scenario: キーボード表示中もタイムラインを読む
- **WHEN** ソフトキーボードが表示された状態でユーザーがタイムラインをスクロールする
- **THEN** システムはタイムラインをスクロール可能に保ち、入力内容を失わない

#### Scenario: セーフエリアを尊重する
- **WHEN** ノッチやホームインジケータを持つ端末で表示する
- **THEN** システムは入力フォームとタイムラインをセーフエリア内に配置し、システム UI と重ならない

### Requirement: iOS からの添付
システムは、iOS において写真ライブラリ、カメラ、およびファイルからの添付を行えるようにしなければならない (SHALL)。

#### Scenario: 写真を添付する
- **WHEN** ユーザーが添付操作から写真ライブラリの画像を選択する
- **THEN** システムは当該画像を添付としてフォームに追加する

#### Scenario: 権限が拒否されている
- **WHEN** 写真またはカメラへのアクセス権限が拒否されている状態でユーザーが添付を試みる
- **THEN** システムは権限が必要である旨と設定への導線を提示し、クラッシュしない

### Requirement: モバイルでのリッチコンテンツ表示
システムは、iOS においても Markdown、シンタックスハイライト付きコードブロック、Mermaid 図を表示しなければならない (SHALL)。

#### Scenario: コードブロックを表示する
- **WHEN** タイムラインに横幅を超えるコードブロックを含むポストが表示される
- **THEN** システムはコードブロック内で横スクロールを提供し、画面全体の横スクロールは発生させない

#### Scenario: Mermaid 図を表示する
- **WHEN** タイムラインに `mermaid` コードブロックを含むポストが表示される
- **THEN** システムは図を描画して表示し、描画できない場合はソースコードとして表示する

#### Scenario: 描画の負荷を抑える
- **WHEN** タイムラインに Mermaid を含むポストが多数存在する
- **THEN** システムは可視範囲に入ったポストのみ図を描画し、同時に生成する描画コンテキストの数に上限を設ける

### Requirement: バックグラウンド復帰時の更新
システムは、アプリがバックグラウンドから復帰したとき、表示中の内容を最新化しなければならない (SHALL)。

#### Scenario: 復帰時に差分を取得する
- **WHEN** アプリがバックグラウンドから復帰する
- **THEN** システムは切断中に発生した変更を取得し、表示中のタイムラインとチャネルツリーを更新する
