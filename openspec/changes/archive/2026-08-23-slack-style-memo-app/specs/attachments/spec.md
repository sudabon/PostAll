## ADDED Requirements

### Requirement: ポストへの添付
システムは、1 つのポストに対して複数のファイルを添付できるようにしなければならない (SHALL)。添付はポストと同時に保存され、ポストの表示時に一覧されなければならない (SHALL)。

#### Scenario: 添付付きのポストを作成する
- **WHEN** ユーザーが本文と 1 つ以上の添付を伴ってポストを送信する
- **THEN** システムはポストと添付を保存し、タイムライン上で本文の下に添付を表示する

#### Scenario: 本文なしで添付のみ投稿する
- **WHEN** ユーザーが本文を空にしたまま添付のみでポストを送信する
- **THEN** システムはポストを作成し、添付のみを表示する

### Requirement: 実体はオブジェクトストレージに保存する
システムは、添付の実体を S3 バケットに保存し、データベースにはメタデータ（ファイル名・形式・サイズ・保存キー・チェックサム）のみを保持しなければならない (SHALL)。バケットをパブリック読み取り可能にしてはならない (MUST NOT)。

#### Scenario: 添付を保存する
- **WHEN** 添付のアップロードが完了する
- **THEN** システムは実体を S3 に保存し、データベースには当該オブジェクトを指すメタデータのみを記録する

#### Scenario: バケットへの直接アクセス
- **WHEN** 署名を伴わない要求が S3 のオブジェクトへ直接アクセスを試みる
- **THEN** システムは内容を返さない

### Requirement: 署名付き URL によるアップロード
システムは、クライアントが署名付き URL を用いて S3 へ直接アップロードできるようにしなければならない (SHALL)。署名付き URL の発行時に、サーバがサイズと形式の制約および認可を検証しなければならない (SHALL)。

#### Scenario: アップロード用の URL を得る
- **WHEN** クライアントがファイル名・形式・サイズを伴ってアップロードの開始を要求する
- **THEN** サーバは制約と認可を検証したうえで、有効期限付きのアップロード用 URL を返す

#### Scenario: アップロードを完了として確定する
- **WHEN** クライアントが S3 へのアップロード後に完了を通知する
- **THEN** システムは添付のメタデータをポストに紐付けて確定し、ポストの表示に含める

#### Scenario: 完了が通知されない
- **WHEN** アップロード用 URL が発行された後、一定時間を過ぎても完了が通知されない
- **THEN** システムは当該添付を確定せず、保存された実体を回収の対象とする

#### Scenario: 認可されていないアップロード要求
- **WHEN** 認可情報を伴わない要求がアップロード用 URL の発行を求める
- **THEN** サーバは要求を拒否し、URL を発行しない

### Requirement: 署名付き URL によるダウンロード
システムは、認可を検証したうえで、有効期限付きの署名付き URL によって添付をダウンロードできるようにしなければならない (SHALL)。

#### Scenario: 添付をダウンロードする
- **WHEN** ユーザーが添付のダウンロード操作を実行する
- **THEN** システムは認可を検証し、有効期限付きの URL を用いて元のファイル名と内容でファイルを保存させる

#### Scenario: 認可されていない取得要求
- **WHEN** 認可情報を持たない要求が添付の URL 発行を求める
- **THEN** サーバは URL を発行せず、認可エラーを返す

#### Scenario: 期限切れの URL
- **WHEN** 発行済みの署名付き URL が有効期限を過ぎた後に使用される
- **THEN** システムは内容を返さない

### Requirement: 画像添付のインライン表示
システムは、画像形式の添付をタイムライン上でインラインのサムネイルとして表示しなければならない (SHALL)。

#### Scenario: 画像をインライン表示する
- **WHEN** ポストに画像形式の添付が含まれる
- **THEN** システムは縦横比を維持したサムネイルをポスト内に表示する

#### Scenario: 画像を拡大表示する
- **WHEN** ユーザーがサムネイルをクリックまたはタップする
- **THEN** システムは原寸相当の拡大ビューアで画像を表示し、閉じる操作を提供する

#### Scenario: 複数画像を表示する
- **WHEN** ポストに複数の画像添付が含まれる
- **THEN** システムはそれらをグリッド状に並べて表示し、ポストの縦方向を過度に占有しない

#### Scenario: 画像が取得できない
- **WHEN** 画像の取得に失敗する
- **THEN** システムは取得できない旨のプレースホルダを表示し、ポスト全体の表示を壊さない

### Requirement: 非画像ファイルのカード表示
システムは、画像以外の添付をファイル名・拡張子・サイズを含むカードとして表示しなければならない (SHALL)。

#### Scenario: 一般ファイルを表示する
- **WHEN** ポストに画像以外のファイル添付が含まれる
- **THEN** システムはファイル名、形式アイコン、ファイルサイズを含むカードを表示する

### Requirement: アップロードの進捗と失敗処理
システムは、添付のアップロード進行状況を表示し、失敗時には再試行の手段を提供しなければならない (SHALL)。

#### Scenario: アップロード中の表示
- **WHEN** 添付のアップロードが進行中である
- **THEN** システムは当該添付の進捗を表示し、完了するまで送信操作の完了を示さない

#### Scenario: アップロードが失敗する
- **WHEN** 添付のアップロードがネットワークまたはストレージのエラーで失敗する
- **THEN** システムは失敗した添付を明示し、再試行と除去の操作を提供する

### Requirement: サイズと形式の制約
システムは、1 ファイルあたりの最大サイズと 1 ポストあたりの最大添付数を設け、制約を満たさない添付を受理してはならない (MUST NOT)。制約違反はアップロード開始前にユーザーへ通知しなければならない (SHALL)。

#### Scenario: 上限サイズを超えるファイル
- **WHEN** ユーザーが上限サイズを超えるファイルを添付しようとする
- **THEN** システムは当該ファイルを添付せず、上限値を含むエラーメッセージを表示する

#### Scenario: 添付数の上限を超える
- **WHEN** ユーザーが 1 ポストあたりの上限を超える数のファイルを添付しようとする
- **THEN** システムは上限を超える分を追加せず、上限に達した旨を表示する

#### Scenario: サーバ側でも制約を検証する
- **WHEN** クライアントの制約検証を経ずに上限超過のアップロード要求がサーバへ到達する
- **THEN** サーバは署名付き URL を発行せず、制約違反を示すエラーを返す

### Requirement: 添付の破棄
システムは、ポストの論理削除および編集に伴って不要となった添付を回収しなければならない (SHALL)。

#### Scenario: ポスト削除に伴う添付の破棄
- **WHEN** 添付を持つポストが論理削除される
- **THEN** システムは当該ポストの添付を参照不可にし、実体を回収の対象とする

#### Scenario: 編集で添付を外す
- **WHEN** ユーザーがポストの編集で既存の添付を除去して保存する
- **THEN** システムは当該添付をポストから切り離し、実体を回収の対象とする

#### Scenario: 参照されている実体は消さない
- **WHEN** 回収処理が実行される
- **THEN** システムは、いずれかのポストから参照されている実体を削除しない
