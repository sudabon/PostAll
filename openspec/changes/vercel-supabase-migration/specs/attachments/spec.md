## MODIFIED Requirements

### Requirement: 実体はオブジェクトストレージに保存する
システムは、添付の実体をマネージドオブジェクトストレージのバケットに保存し、データベースにはメタデータ（ファイル名・形式・サイズ・保存キー・チェックサム）のみを保持しなければならない (SHALL)。バケットをパブリック読み取り可能にしてはならない (MUST NOT)。添付の実体が API サーバを経由してはならない (MUST NOT)。

#### Scenario: 添付を保存する
- **WHEN** 添付のアップロードが完了する
- **THEN** システムは実体をオブジェクトストレージに保存し、データベースには当該オブジェクトを指すメタデータのみを記録する

#### Scenario: バケットへの直接アクセス
- **WHEN** 署名を伴わない要求がオブジェクトストレージのオブジェクトへ直接アクセスを試みる
- **THEN** システムは内容を返さない

#### Scenario: 実体が API サーバを通らない
- **WHEN** クライアントが添付をアップロードまたはダウンロードする
- **THEN** システムはクライアントとオブジェクトストレージの間で直接転送させ、API サーバの要求・応答のサイズ上限に添付のサイズが影響されないようにする

### Requirement: 署名付き URL によるアップロード
システムは、クライアントが署名付き URL を用いてオブジェクトストレージへ直接アップロードできるようにしなければならない (SHALL)。署名付き URL の発行時に、サーバがサイズと形式の制約および認可を検証しなければならない (SHALL)。

#### Scenario: アップロード用の URL を得る
- **WHEN** クライアントがファイル名・形式・サイズを伴ってアップロードの開始を要求する
- **THEN** サーバは制約と認可を検証したうえで、有効期限付きのアップロード用 URL と、アップロード時に付与すべきヘッダを返す

#### Scenario: 指定と異なる内容をアップロードする
- **WHEN** クライアントが、発行時に申告したサイズまたは形式と異なる内容をアップロードしようとする
- **THEN** システムは当該アップロードを成功として確定しない

#### Scenario: アップロードを完了として確定する
- **WHEN** クライアントがオブジェクトストレージへのアップロード後に完了を通知する
- **THEN** システムは実体の存在とサイズを検証したうえで、添付のメタデータをポストに紐付けて確定し、ポストの表示に含める

#### Scenario: 完了が通知されない
- **WHEN** アップロード用 URL が発行された後、一定時間を過ぎても完了が通知されない
- **THEN** システムは当該添付を確定せず、保存された実体を回収の対象とする

#### Scenario: 認可されていないアップロード要求
- **WHEN** 認可情報を伴わない要求がアップロード用 URL の発行を求める
- **THEN** サーバは要求を拒否し、URL を発行しない

### Requirement: 署名付き URL によるダウンロード
システムは、認可を検証したうえで、有効期限付きの署名付き URL によって添付をダウンロードできるようにしなければならない (SHALL)。

#### Scenario: 添付をダウンロードする
- **WHEN** ユーザーが添付のダウンロード操作を実行する
- **THEN** システムは認可を検証し、有効期限付きの URL を用いて元のファイル名と内容でファイルを保存させる

#### Scenario: 認可されていない取得要求
- **WHEN** 認可情報を持たない要求が添付の URL 発行を求める
- **THEN** サーバは URL を発行せず、認可エラーを返す

#### Scenario: 期限切れの URL
- **WHEN** 発行済みの署名付き URL が有効期限を過ぎた後に使用される
- **THEN** システムは内容を返さない

### Requirement: 添付の破棄
システムは、ポストの論理削除および編集に伴って不要となった添付を回収しなければならない (SHALL)。回収処理は、スケジューラからの起動によって定期的に実行されなければならない (SHALL)。

#### Scenario: ポスト削除に伴う添付の破棄
- **WHEN** 添付を持つポストが論理削除される
- **THEN** システムは当該ポストの添付を参照不可にし、実体を回収の対象とする

#### Scenario: 編集で添付を外す
- **WHEN** ユーザーがポストの編集で既存の添付を除去して保存する
- **THEN** システムは当該添付をポストから切り離し、実体を回収の対象とする

#### Scenario: 参照されている実体は消さない
- **WHEN** 回収処理が実行される
- **THEN** システムは、いずれかのポストから参照されている実体を削除しない

#### Scenario: 回収処理が定期的に走る
- **WHEN** スケジュールされた時刻が到来する
- **THEN** システムは回収対象の添付を処理し、常駐するプロセスを必要としない

#### Scenario: 実体の削除に失敗する
- **WHEN** 回収処理がオブジェクトストレージからの削除に失敗する
- **THEN** システムは当該添付を回収済みとして扱わず、失敗を記録して次回の実行で再試行する
