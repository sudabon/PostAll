## Why

ポストの編集とリアクションは楽観的更新になったが、新規投稿・返信・削除は「押してからサーバーの応答を待つ」操作のまま残っている。新規投稿は応答が返るまで入力フォームが無効化されたうえ、再取得が終わるまでタイムラインに現れない。削除は確認ダイアログを承認しても行が画面に残り続ける。同じアプリの中で、編集だけが速く、投稿と削除だけが遅いという一貫性の欠如が生じている。

`sync-and-storage` の「投稿がサーバーで失敗する」および `post-timeline` の「投稿直後の反映」は、既に即時反映と失敗時の再送・破棄を要求しており、現在の実装はこの要求を満たしていない。

## What Changes

- 新規投稿・返信を楽観的更新にする。送信操作の直後にサーバーの応答を待たず、入力フォームを空にし、タイムラインまたはスレッドの末尾へ当該ポストを表示する。
- サーバー確定前のポストは、送信中であると分かる控えめな表示（通常より薄い表示）にする。id がまだ確定していないため、編集・削除・リアクション・スレッドを開く操作は当該ポストに対して提供しない。
- 応答が返った時点で、サーバーが返した内容の通常のポストへ差し替える。差分が無ければ本文の表示は変化しない。
- 送信がサーバーで失敗した場合は、当該ポストをその位置に残したまま失敗状態として示し、再送と破棄をユーザーに選ばせる。入力フォームは空のままとし、失敗を待つ間に書き始めた次の入力を潰さない。
- 削除を楽観的更新にする。確認ダイアログの承認直後に、サーバーの応答を待たず当該ポストをタイムラインおよびスレッドの表示から取り除く。
- 削除がサーバーで失敗した場合は、当該ポストを元の位置へ戻し、その行の中に失敗を示したうえで再試行の操作を提供する。
- 接続できない状態での送信は、従来どおり入力をフォームに残して失敗を示す。保留中のポストを作らない。オンラインでサーバーが拒否した場合のみ、上記の失敗状態のポストになる。
- 対象はチャネル直下のポストの投稿と削除、およびスレッド内の返信の投稿と削除。編集の処理フローは変更しない。

破壊的変更なし。API の要求・応答の形は変わらない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `post-timeline`: 「投稿直後の反映」に、サーバーの応答を待たずに末尾へ表示すること・確定前の表示と操作の制限・確定時の差し替えを追加する。「ポストの論理削除」に、承認直後に表示から取り除くことと失敗時に元の位置へ戻すことを追加する。
- `post-threads`: 「ポストへの返信」に、返信も同じ即時反映の規則に従うことを明示する。「スレッド内ポストの編集と削除」に、返信の削除も即時反映と失敗時の復帰に従うことを追加する。「返信件数の表示」に、確定前の返信を件数に数えないことを明示する。
- `post-composer`: 「ポストの送信」に、送信操作の直後にフォームを空にすること・失敗時に入力をフォームへ戻さないことを追加する。「下書きの保持」の下書き削除の契機を、送信の成功から送信操作の時点へ変更する。
- `sync-and-storage`: 「楽観的更新と失敗時の巻き戻し」に、削除がサーバーで失敗したときのシナリオを追加する。

## Impact

フロントエンドのみ。バックエンド・API スキーマ・データベースは変更しない。

- `frontend/src/state/ui.ts` — 確定前のポストと削除中のポストを保持する状態を追加する。
- `frontend/src/hooks/usePosts.ts` — `create` / `reply` / `remove` mutation を `onMutate` / `onError` / `onSuccess` / `onSettled` 構成へ。
- `frontend/src/lib/post-cache.ts` — 確定したポストの挿入と削除済みポストの除去をキャッシュへ適用する関数を追加する。
- `frontend/src/components/timeline/Timeline.tsx` / `frontend/src/components/thread/ThreadPanel.tsx` — 確定前のポストを取得結果へ重ねて描画し、削除中のポストを除外する。送信の呼び出しを「待たずに返す」へ。
- `frontend/src/components/post/` — 送信中・送信失敗・削除失敗の行表示を追加する。

既存の楽観的更新（`frontend/src/hooks/useReactions.ts` および `usePosts.ts` の `edit`）と同じ mutation 構成を踏襲するため、新しい依存やライブラリの追加は無い。
