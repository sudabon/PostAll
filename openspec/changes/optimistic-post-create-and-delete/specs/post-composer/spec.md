## MODIFIED Requirements

### Requirement: ポストの送信
システムは、明示的な送信操作によってポストを作成しなければならない (SHALL)。本文が空かつ添付も無い状態での送信を許可してはならない (MUST NOT)。

システムは、送信操作の直後に入力フォームを空にしなければならない (SHALL)。サーバーの応答を待って入力フォームを空にしてはならない (MUST NOT)。応答を待つ間、入力フォームを操作できない状態にしてはならない (MUST NOT)。

送信がサーバーで拒否された場合、システムは入力内容を入力フォームへ書き戻してはならない (MUST NOT)。失敗した内容は、タイムラインまたはスレッドビュー上の失敗したポストとして保持しなければならない (SHALL)。

ただし接続できない状態での送信に対しては、システムは送信を行わず、入力内容を入力フォームに残さなければならない (SHALL)。

#### Scenario: キーボードで送信する
- **WHEN** デスクトップまたはブラウザでユーザーが Enter キーを押す
- **THEN** システムは入力内容を新規ポストとして送信し、サーバーの応答を待たずにフォームを空にする

#### Scenario: 送信ボタンで送信する
- **WHEN** ユーザーが送信ボタンを押す
- **THEN** システムは入力内容を新規ポストとして送信し、サーバーの応答を待たずにフォームを空にする

#### Scenario: 空の送信を拒否する
- **WHEN** ユーザーが本文も添付も無い状態で送信操作を行う
- **THEN** システムは送信を行わず、フォームの内容とフォーカスを維持する

#### Scenario: 送信中の多重送信を防ぐ
- **WHEN** 送信処理が進行中にユーザーが再度送信操作を行う
- **THEN** システムは重複したポストを作成しない

#### Scenario: 送信直後に次の入力を始める
- **WHEN** ユーザーが送信操作の直後、先の送信の応答が返る前に次の本文を入力する
- **THEN** システムは入力を受け付け、先の送信の結果によって入力中の内容を書き換えない

#### Scenario: 送信に失敗しても入力を失わない
- **WHEN** サーバーのエラーで送信が失敗する
- **THEN** システムは失敗した内容を当該ポストの失敗状態として保持して再送できるようにし、入力フォームの内容は変更しない

#### Scenario: 接続できない状態で送信する
- **WHEN** 接続できない状態でユーザーが送信操作を行う
- **THEN** システムは送信を行わず、入力内容を入力フォームに残したまま、送信できなかったことを示す

### Requirement: 下書きの保持
システムは、未送信の入力内容をチャネルごと（およびスレッドごと）の下書きとして保持しなければならない (SHALL)。下書きは切り替えおよびアプリ再起動をまたいで復元されなければならない (SHALL)。

編集モードの入力内容を下書きとして永続化してはならない (MUST NOT)。編集モードは、当該チャネルまたはスレッドの新規投稿の下書きを読み込んでも上書きしてもならない (MUST NOT)。

送信に失敗したポストの内容を下書きとして永続化してはならない (MUST NOT)。その内容は失敗したポストの表示として保持する。

#### Scenario: チャネルを切り替えて戻る
- **WHEN** ユーザーがテキスト入力中に別チャネルへ切り替え、元のチャネルへ戻る
- **THEN** システムは元のチャネルの下書きを入力フォームへ復元する

#### Scenario: アプリを再起動する
- **WHEN** ユーザーが下書きを残したままアプリを終了し、再起動する
- **THEN** システムは当該チャネルの下書きを復元する

#### Scenario: 送信後に下書きを消す
- **WHEN** ユーザーが送信操作を行い、システムがポストを即時表示する
- **THEN** システムはサーバーの応答を待たずに当該チャネルまたはスレッドの下書きを削除する

#### Scenario: 送信できなかったときは下書きを残す
- **WHEN** 接続できない状態でユーザーが送信操作を行う
- **THEN** システムは下書きを削除せず、入力内容を下書きとして保持する

#### Scenario: 失敗したポストは再起動をまたがない
- **WHEN** 送信に失敗したポストが画面に残っている状態でユーザーがアプリを終了し、再起動する
- **THEN** システムは当該ポストを復元せず、下書きにも復元しない

#### Scenario: 編集中の内容は下書きにしない
- **WHEN** ユーザーが編集モードで本文を書き換えたまま編集を取り消す
- **THEN** システムは書き換えた内容を保持せず、新規投稿の入力フォームの下書きも変更しない
