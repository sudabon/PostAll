## MODIFIED Requirements

### Requirement: 投稿直後の反映
システムは、ユーザーが新規ポストを投稿したとき、そのポストをタイムライン末尾へ即座に追加しなければならない (SHALL)。

システムは、送信操作に対して、サーバーの応答を待たずに当該ポストをタイムライン末尾へ表示しなければならない (SHALL)。応答が返るまで送信操作を待機状態として提示してはならない (MUST NOT)。

サーバーが確定する前のポストは、確定済みのポストと区別できる控えめな表示にしなければならない (SHALL)。確定前のポストに対して、編集・削除・リアクション・スレッドを開く操作を提供してはならない (MUST NOT)。

応答が返った時点で、システムはサーバーが確定したポストへ表示を差し替えなければならない (SHALL)。差し替えの前後で本文・添付・並び順に差分が無い場合、表示を変化させてはならない (MUST NOT)。

接続できない状態での送信に対しては、ポストをタイムラインへ表示してはならない (MUST NOT)。

#### Scenario: 自分の投稿が末尾に追加される
- **WHEN** ユーザーが入力フォームからポストを送信する
- **THEN** システムはサーバーの応答を待たずにタイムライン末尾に当該ポストを表示し、末尾までスクロールする

#### Scenario: 確定前のポストは操作できない
- **WHEN** 送信したポストがまだサーバーで確定していない
- **THEN** システムは当該ポストを確定済みと区別できる表示にし、編集・削除・リアクション・スレッドを開く操作を提供しない

#### Scenario: 確定した内容へ差し替える
- **WHEN** 送信したポストに対するサーバーの応答が返る
- **THEN** システムは当該ポストをサーバーが確定した内容の通常のポストへ差し替え、以後は編集・削除・リアクション・スレッドの操作を提供する

#### Scenario: 送信が失敗する
- **WHEN** ポスト送信がサーバーエラーで失敗する
- **THEN** システムは当該ポストをタイムライン上のその位置に残したまま失敗状態として表示し、再送および破棄の操作を提供したうえで、入力内容を失わせない

#### Scenario: 失敗したポストを再送する
- **WHEN** ユーザーが失敗状態のポストに対して再送を選ぶ
- **THEN** システムは同じ本文と添付でサーバーへ再度送信し、当該ポストを送信中の表示へ戻す

#### Scenario: 失敗したポストを破棄する
- **WHEN** ユーザーが失敗状態のポストに対して破棄を選ぶ
- **THEN** システムは当該ポストをタイムラインの表示から取り除き、サーバーへの送信を行わない

#### Scenario: 接続できない状態で送信する
- **WHEN** 接続できない状態でユーザーがポストを送信する
- **THEN** システムはタイムラインへ当該ポストを表示せず、入力内容を入力フォームに残したまま送信できなかったことを示す

### Requirement: ポストの論理削除
システムは、ポストの削除を論理削除として実行しなければならない (SHALL)。削除されたポストは通常の取得結果に含まれてはならない (MUST NOT)。削除は実行前に確認を求めなければならない (SHALL)。

システムは、削除の承認に対して、サーバーの応答を待たずに当該ポストをタイムラインの表示から取り除かなければならない (SHALL)。応答が返るまで削除操作を待機状態として提示してはならない (MUST NOT)。

削除がサーバーで失敗した場合、システムは当該ポストを元の位置へ戻さなければならない (SHALL)。戻したポストには削除できなかったことを示し、再試行の操作を提供しなければならない (SHALL)。失敗した削除を成功として表示から消したままにしてはならない (MUST NOT)。

#### Scenario: ポストを削除する
- **WHEN** ユーザーがポストの削除を実行し、確認ダイアログで承認する
- **THEN** システムはサーバーの応答を待たずに当該ポストをタイムラインの表示から取り除き、サーバーへ論理削除を要求する

#### Scenario: 削除がサーバーで失敗する
- **WHEN** クライアントがポストを表示から取り除いた後、サーバーがその削除を拒否する
- **THEN** システムは当該ポストを元の位置へ戻し、その位置に削除できなかったことを示し、再試行の操作を提供する

#### Scenario: 失敗した削除を再試行する
- **WHEN** ユーザーが削除に失敗したポストの再試行を選ぶ
- **THEN** システムは確認を求め直さずにサーバーへ再度削除を要求し、当該ポストを再び表示から取り除く

#### Scenario: 削除されたポストは取得されない
- **WHEN** 削除済みのポストを含む範囲をタイムラインが取得する
- **THEN** システムは削除済みのポストを応答に含めない

#### Scenario: 削除を取り消す
- **WHEN** ユーザーが削除の確認ダイアログで取り消しを選ぶ
- **THEN** システムはポストを保持し、タイムラインを変更しない

#### Scenario: 削除されたポストは編集できない
- **WHEN** 削除済みのポストに対する編集要求がサーバへ到達する
- **THEN** サーバは要求を拒否する
